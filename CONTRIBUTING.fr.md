# Contribuer à OSSIF

## La règle la plus importante

Apportez des preuves. Si vous n'êtes pas d'accord avec quelque chose, expliquez pourquoi avec des affirmations vérifiables. Si vous proposez quelque chose de nouveau, montrez votre raisonnement. « J'ai l'impression que... » est un point de départ pour la conversation. « Voici la preuve que... » est ce qui modifie les documents.

## Comment participer

### Lire et réfléchir
Cela compte. Vous n'avez pas besoin d'écrire du code ou de soumettre des pull requests pour participer à OSSIF. Comprendre le cadre et appliquer ses outils de raisonnement dans votre propre vie est la forme de contribution la plus fondamentale.

### Ouvrir des issues
Vous avez trouvé une erreur ? Vous voyez une lacune ? Vous n'êtes pas d'accord avec une position ? Ouvrez une issue GitHub. Soyez précis sur ce qui ne va pas selon vous et pourquoi. Incluez des preuves si possible. Même un commentaire comme « cette section est confuse » est un retour utile.

### Proposer des changements
Forkez le dépôt, effectuez vos modifications et soumettez une pull request. Pour les changements de contenu, votre PR devrait inclure :

- Ce que vous avez changé
- Pourquoi vous l'avez changé
- Quelles preuves soutiennent le changement
- Quels compromis le changement introduit

### Construire des outils
The Primer, le Portail de Conversation Avatar, le système de Jeton de Confiance et les autres composants technologiques décrits dans [technology.md](docs/technology.md) sont des conceptions qui attendent des bâtisseurs. Si vous souhaitez implémenter quelque chose, ouvrez d'abord une issue pour discuter de votre approche.

### Traduire
OSSIF devrait être accessible dans toutes les langues. Si vous pouvez traduire un document, c'est une contribution d'une valeur inestimable.

### Enseigner
Si vous utilisez les principes d'OSSIF dans une salle de classe, un atelier, une réunion communautaire ou une conversation — et que vous apprenez quelque chose sur ce qui fonctionne et ce qui ne fonctionne pas — partagez-le. Ouvrez une issue avec vos observations.

## Processus de modification des documents

Les modifications apportées aux documents ont des seuils différents selon leur niveau :

- **Fautes de frappe, mise en forme, liens morts** : Soumettez simplement une PR. C'est de la maintenance.
- **Clarifications et exemples** : Soumettez une PR avec une brève explication.
- **Nouveau contenu ou reformulation importante** : Ouvrez d'abord une issue pour discussion, puis soumettez une PR.
- **Changements apportés aux valeurs ou principes fondamentaux** : Ceux-ci nécessitent une discussion communautaire plus large et un seuil de consensus plus élevé. Ouvrez une issue, laissez du temps pour la délibération et documentez soigneusement le raisonnement.

## Code de conduite

Respectez les Sept Impératifs. Plus précisément :

- Engagez-vous de bonne foi — supposez que les autres essaient d'aider, pas d'attaquer
- Utilisez des preuves et le raisonnement, pas des attaques personnelles
- Respectez le temps et les efforts des autres contributeurs
- Acceptez que vous puissiez avoir tort — et soyez prêt à mettre à jour votre position
- N'utilisez pas les espaces OSSIF pour recruter pour d'autres causes, vendre des produits ou faire votre propre promotion

## Ce que nous n'acceptons pas

- Les changements qui violent les Engagements Fondamentaux sans justification basée sur des preuves
- Le contenu qui déshumanise tout groupe ou individu
- Les affirmations non réfutables présentées comme des faits établis
- Le vandalisme, le spam ou les perturbations délibérées de mauvaise foi (les arguments selon lesquels le cadre est fondamentalement erroné ne sont pas seulement autorisés — ils sont essentiels. Le sabotage n'est pas la même chose que la dissidence.)

## Des questions ?

Ouvrez une issue avec le label « question ». Il n'y a pas de questions stupides — seulement des questions qui n'ont pas encore été posées.

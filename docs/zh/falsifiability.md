# 可证伪性

OSSIF 声称重视可证伪性。本文件旨在将这一主张落到实处。如果 OSSIF 无法明确其自身失败的条件，那么“可证伪性”就只是虚名，而非实践。

## 证明 OSSIF 错误的条件

以下是该框架应被视为失败的条件。这些条件并非详尽无遗，且应随着我们认知的深入而进行修订——但它们必须存在，因为一个无法描述自身失败模式的系统是不可信的。

### The Primer 未能提高推理能力

如果在构建并部署了 The Primer 后，对照评估显示参与者在评估主张、识别谬误或进行基于证据的推理方面的能力没有任何可衡量的提升，那么其核心教育论题就是错误的。这并不意味着 OSSIF 毫无价值，但这意味着其核心机制不起作用，必须重新设计或弃用。

**衡量标准：** 对 The Primer 用户与对照组的批判性思维技能进行前测/后测评估。
**时间范围：** 在 The Primer 功能性部署后的 2 年内。

### 未形成社区

如果在公开可用 3 年后，除了创始人之外没有任何社区实质性地参与——没有贡献者、没有分支（forks）、没有采用——那么 OSSIF 就未能证明其方法能引起创造者之外任何人的共鸣。一个无法吸引集体参与的集体推理框架只是一本日志，而非框架。

**衡量标准：** 贡献者数量、分支数量、外部采用情况、社区治理参与度。
**时间范围：** 自初次发布起 3 年。

### 治理结构未能防止控制权攫取

如果 OSSIF 的治理得以实施，但权力仍然以框架旨在防止的方式集中——如创始人控制、捐赠者控制、派系控制——且自我修正机制未能解决这一问题，那么其结构性论题就是错误的。

**衡量标准：** 独立治理审计、权力集中度指标、价值成本日志是否显示了实际承担的成本。
**时间范围：** 从治理结构运行之日起持续进行。

### 框架产生的结果与其自身价值相悖

如果根据 OSSIF 自身设定的指标，其流程持续产生的政策或决策导致痛苦增加、理解减少或权力集中，那么该方法就没有产生预期的结果。应修订该方法或解散该框架。

**衡量标准：** 根据七项准则进行结果追踪。
**时间范围：** 持续进行。

### 理事会的建议被持续忽略

如果审议理事会（或任何继任审查机构）提出了实质性建议，而这些建议在没有公布反驳理由的情况下被系统性地不予执行，那么自我修正机制就只是摆设。这并非虚构——它已经发生过，而本文件的存在在一定程度上正是因为那次失败。

**衡量标准：** 建议执行率，以及针对任何拒绝执行的情况所公布的理由。
**时间范围：** 持续进行。在每次理事会会议上进行审查。

## 实践中的证伪形式

证伪并不意味着“OSSIF 被摧毁”。它意味着：

1. 公开承认特定失败
2. 在代码库中记录证据
3. 对受影响的组件进行修订、更换或移除
4. 如果失败足够根本，则考虑解散（参见 [governance.md](governance.md)）

一个能够说出“我们在这件事上错了”的框架，比一个做不到这一点的框架更强大。一个从未承认过错误的框架，要么从未经受过考验，要么从未诚实过。

## 关于本文件

本文件应当让人感到不安。如果没有这种感觉，说明它还不够具体。随着 OSSIF 的发展以及失败条件变得更加清晰，本文件将进行修订——但它绝不能空洞，也绝不能模糊到其本身无法被证伪。

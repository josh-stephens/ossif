# 治理

本文件描述了 OSSIF 的实际治理方式——不是它某天渴望达到的治理方式，而是目前谁掌握权力，决策如何做出，以及存在哪些约束。如果地图与实际地形不符，那是地图的问题。

## 现状：创始人控制

截至本文撰写时，OSSIF 由一个人控制：**Josh Stephens** (GitHub: josh-stephens)。

Josh 控制着：
- GitHub 仓库（合并权限、分支保护、设置）
- 理事会会议提示词与架构
- 贡献指南
- 所有文件的叙述与构架
- 决定哪些内容可以发布，哪些不能

这不是秘密，也不是永久性的。但这必须被明确阐述，因为一个声称防止权力集中、却又将权力集中于一人之手的框架存在**公信力问题**——即便这种集中是暂时的且出于好意。

## 决策流程

### 当前（社区建立前）

在 OSSIF 除了创始人之外还没有形成有意义的社区时：
- 创始人做出所有决策
- 联合智慧体理事会提供对抗性审查
- 理事会的建议会被跟踪，其落实状态是公开的（见下文）
- 所有决策都记录在仓库的提交历史（commit history）中

### 目标（社区建立后）

一旦社区建立：
- **普通决策**（澄清、示例、维护）：任何贡献者都可以提交 PR，由任何维护者合并
- **重大变更**（新内容、措辞修改）：需要进行议题讨论，在听取社区意见后合并
- **基本变更**（核心价值、治理结构）：正式提案，90 天审议期，绝对多数投票通过
- **解散**：见下文

## 创始人约束

以下约束立即适用于创始人：

1. **禁止单方面修改基本承诺。** 一旦社区建立，创始人不得单独更改 values.md 中的价值观。
2. **理事会的建议必须公开发布回应。** 禁止未经解释就忽略建议。可以不同意，但不能保持沉默。
3. **创始人不得单独削弱本治理文件。** 任何减少问责、移除约束或集中权力的变更，都必须经过与基本变更相同的流程。
4. **创始人可以被罢免。** 如果社区规模达到可以进行治理转型的程度（10 名以上活跃贡献者），则开启罢免程序：三分之一成员提议，简单多数投票通过。

### 外部强制执行

自我约束的价值完全取决于施加约束者的诚信。为了使这些约束真实有效，以下外部强制执行机制现已生效：

1. **理事会对基本变更的否决权。** 联合智慧体理事会可以审查任何对 values.md、governance.md 或基本承诺的拟议变更。如果理事会多数席位反对该变更并公布理由，则该变更将被阻断，直到通过公开审议过程解决异议。创始人无法否决理事会的否决权——唯一的途径是说服。

2. **公开变更日志。** 对 governance.md、values.md、CONTRIBUTING.md 和 falsifiability.md 的每一次修改都会在 git 中记录完整的差异历史。理事会和社区可以审计任何变更。未经公开解释就撤回约束，其本身就是触发可证伪性的行为。

3. **达到阈值时的社区否决。** 一旦存在 5 名以上活跃贡献者（定义为：在过去 6 个月内提交过至少一个已合并的 PR 或实质性议题），治理变更需要经过 30 天的公开征求意见期，并获得活跃贡献者的多数批准。创始人的投票计为一票。

4. **不可剥夺的理事会访问权。** 创始人不得撤销或限制理事会对 OSSIF 进行评估的能力。理事会会议提示词、过程和报告发布在另一个独立的仓库中 (josh-stephens/united-sapients)，该仓库不完全受创始人控制——一旦达到上述社区阈值，任何社区成员都可以发起理事会会议。

这些机制尚不完善且会不断演进。但它们是具有可观测后果的真实约束，而非愿景。

## 落日审查

每一项结构性决策、政策立场和治理机制都必须按固定时间表进行强制审查：

- **政策立场** (platform.md)：每 2 年审查一次
- **治理结构**：每 3 年审查一次
- **基本承诺**：每 5 年审查一次
- **审查执行人**：由未参与原始决策的成员以及至少一次理事会会议共同进行

审查并不意味着必须做出改变。它意味着会根据证据*考虑*是否改变，并将保留或修订的决定记录在案。

## 解散标准

如果发生以下情况，OSSIF 应当终止存在：

1. **框架未能通过其自身的可证伪性测试**（见 [falsifiability.md](falsifiability.md)）且无法通过修订解决失败之处
2. **治理结构被俘获**，且自我修正机制未能恢复问责制
3. **框架造成了净损害**——如果有证据表明 OSSIF 增加了痛苦、集中了权力或退化了理性，而非改善了它们
4. **社区投票解散**——在审议期后，通过绝对多数投票决定

解散意味着：仓库被归档（而非删除），所有文档根据其知识共享（Creative Commons）许可协议继续公开提供，并由一份最终报告记录哪些行之有效、哪些失败了以及原因。

一个无法描述其自身终结条件的组织是不值得信任的。设立本节是为了让 OSSIF 在必要时能体面地退出。
